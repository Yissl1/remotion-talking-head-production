# 插画素材接入规则

本文件只定义剪辑 Skill 如何接入插画，不修改独立插画 Skill。生成插画时必须调用：

```text
C:\Users\11066\.codex\skills\ian-xiaohei-illustrations\SKILL.md
```

## 边界

- 独立插画 Skill 的提示词模板、Visual DNA、专属 IP 规则、文件命名和 QA 原样保留。
- 本 Skill 不把插画改造成 MG，也不把插画当作新的包装组件。
- 插画和用户提供的视频、截图、图片、Logo 一样，是脚本中的一种普通媒体素材；它只在对应 SRT 语义开始后出现。
- 未经用户选择确认的插画不得进入 `edit-script.json`、30 秒预览或完整成片。用户也可以明确说本期不需要插画。

## 接入流程

1. 分析 SRT 与真实素材，列出适合插画化的语义 cue，并为每张图生成唯一文件名。
2. 调用独立插画 Skill，逐张生成，不拼图、不批量拼成一张画布。
3. 展示每张插画、文件名、对应 cue、表达目的和建议时间区间。
4. 等待用户选择/确认；用户可选择编号、要求重做某张，或明确不需要插画。
5. 只有完成确认后，才在第二步脚本中把选中的插画登记为媒体素材。

建议登记字段：

```json
{
  "path": "C:/project/assets/illustrations/01-topic.png",
  "filename": "01-topic.png",
  "srtCueIds": [3, 4],
  "start": 12.4,
  "end": 17.8,
  "semanticCue": "对应的 SRT 语义",
  "purpose": "解释流程/对比/概念隐喻",
  "status": "selected"
}
```

## 默认呈现

- 默认场景：`illustration` + `SingleImageEvidence`。
- 默认放在人物口播画面右侧安全区，保持完整可读，静态图使用 `contain`；人物脸、嘴、手和字幕安全区优先。
- 只有用户明确要求或脚本语义确实需要，才切换到 `two-thirds-panel` 或 `full-material`；素材类型本身不会自动触发全屏。
- 插画入场可以使用一次性揭示、轻推或克制淡入；进入停留后保持稳定，不持续抖动、呼吸缩放、漂移、循环缩放或重复 seek。
- 插画默认不使用 `OperationDemoPanel`，不添加鼠标追踪、放大追踪或聚焦圈；这些只属于真实操作演示素材。
- 插画可与原有信息组件、字幕和背景艺术字交替使用，但不能改变既有 `deposited-final-v1` 的风格。

## 几何与同步

- 脚本先建立人物安全区、插画区、其他素材区、组件区和字幕区的矩形表。任意一帧可见安全矩形不得相交。
- 插画不能挡脸、挡嘴、挡手、压字幕，也不能与信息卡、图标、人物圆窗或其他素材重叠。若空间不足，先重新排版或让旧组件退场，再让插画进入。
- `startFrame`、`endFrame`、`safeRect`、`noSpoilerBefore` 和 `srtCueIds` 必须写入脚本；插画不得提前剧透产品名、数字、步骤或结论。
- 插画结束后可在交接期间短暂停留，但新语义组件进入前要完成安全的退场或迁移；不得出现留白突变、闪屏、黑帧或单帧重叠。

## 可选组件映射

- `SingleImageEvidence`：单张插画，默认选择。
- `EvidenceFrame`：需要统一证据标签或边界时使用。
- `DemoPanel`：插画需要与证据台统一约 2/3 屏布局时使用。
- 不自动调用 `OperationDemoPanel`、`ImageSpread` 或 MG 组件；只有脚本语义和用户确认明确要求时才使用。

## 验收

在进入脚本确认前至少检查：

- 只引用用户已确认的插画；
- 每张插画与 SRT cue 语义和时间码对应；
- 首帧、停留帧、退场帧和交接帧没有重叠、挡脸、挡字幕、闪屏或黑帧；
- 插画不是静默替代真实素材，若真实素材已经能清楚证明观点，应优先保留真实素材；
- 插画没有改变原有字幕、背景、信息组件、操作演示追踪、音效和渲染门控。
